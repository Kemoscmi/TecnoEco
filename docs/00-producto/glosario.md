# Glosario de TecnoEco

Documenta únicamente conceptos que podemos describir actualmente. Las descripciones orientan la conversación; no fijan entidades, cardinalidades, permisos ni flujos. Se conserva la condición inicial de `Pendiente de definición` para las reglas o detalles aún no acordados.

| Concepto | Descripción actual | Aspectos pendientes |
| --- | --- | --- |
| Solicitud/Ticket | Expresión de un problema, consulta, necesidad o sugerencia de un usuario. Ticket es también el registro utilizado por el prototipo. No se convierte automáticamente en bug. | Pendiente de definición: distinción definitiva entre solicitud y ticket, tipos y estados. |
| Solicitante | Persona que plantea una solicitud. | Pendiente de definición: identidad y relación con usuarios/clientes. |
| Cliente | Quien recibe atención y podría crear y seguir solicitudes mediante el portal previsto. | Pendiente de definición: estructura de empresas/clientes y representación. |
| Solicitud interna | Necesidad planteada desde el ámbito interno de la organización. | Pendiente de definición: identificación y tratamiento. |
| Incidencia | Situación o problema reportado que requiere análisis o atención; no presupone un defecto de software. | Pendiente de definición: clasificación y relación con otros conceptos. |
| Consulta | Pregunta o petición de orientación que puede resolverse mediante soporte o conocimiento. | Pendiente de definición: flujo de atención. |
| Sugerencia/Mejora | Propuesta para mejorar un producto, servicio o proceso. No implica aceptación automática ni trabajo comprometido. | Pendiente de definición: evaluación y formalización. |
| Trabajo técnico | Trabajo que Tecnología realiza para atender necesidades; puede incluir bugs, tareas o mejoras/historias. | Pendiente de definición: estructura y relaciones con solicitudes. |
| Bug | Defecto de software identificado tras el análisis técnico. Una solicitud no es automáticamente un bug. | Pendiente de definición: criterios y ciclo de vida. |
| Historia de usuario | Descripción de una necesidad desde la perspectiva del usuario y del valor esperado. | Pendiente de definición: formato, criterios y flujo. |
| Tarea técnica | Trabajo técnico concreto para construir, mantener, configurar o apoyar una solución. | Pendiente de definición: clasificación y relaciones. |
| Épica | Agrupación conceptual de trabajo de mayor alcance cuyo proceso debería conservar historial. | Pendiente de definición: jerarquía y reglas de agrupación. |
| QA | Aseguramiento de calidad; contempla verificar resultados y conservar trazabilidad. El estado de tablero actual no es un módulo completo de pruebas. | Pendiente de definición: flujo, casos y evidencias. |
| Actividad | Registro de una actuación o comentario. En el prototipo puede relacionarse con un ticket o ser general. | Pendiente de definición: alcance y estructura del modelo futuro. |
| Bitácora | Historial que permite reconstruir lo ocurrido durante un proceso. El prototipo registra creación y cambios de estado. | Pendiente de definición: estructura definitiva de auditoría. |
| Nota interna | Anotación destinada al contexto de trabajo interno. La clasificación de visibilidad actual no implementa permisos de acceso. | Pendiente de definición: controles y reglas de visibilidad. |
| Base de conocimiento/Solución | Repositorio previsto de problemas conocidos, procedimientos y soluciones reutilizables. Estado: DISEÑADO / PENDIENTE. | Pendiente de definición: organización y mantenimiento. |
| Gateway | Punto de entrada que enruta solicitudes a la API. El prototipo utiliza YARP entre el frontend y Tecnologia.API. | Pendiente de definición: necesidades de integración futura. |
| Módulo de Tecnología | Producto previsto para centralizar solicitudes, soporte, trabajo técnico y trazabilidad, validado inicialmente mediante TecnoEco. | Pendiente de definición: alcance e integración futura con DrMax. |
| GitHub Issue | Registro en GitHub usado como backlog vivo de requerimientos, ideas, bugs, mejoras, preguntas y decisiones pendientes del prototipo. | Pendiente de definición: posible integración futura con el módulo. |
